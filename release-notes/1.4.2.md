ArcFlare 1.4.2: the phone AI works inside its small memory, and more call-screen fixes.

## Changes you may notice

- **Arc Pocket Agent (the small AI on the phone) now trims a long chat to fit its memory before it sends, instead of failing first.** It replaces the text of older file reads with a short note, then drops the oldest turns, and tells you with the existing "forgotten" note. It never drops your latest question.
- **It can read a long file in parts.** `read_file` takes an optional start position; each part is sized to the room left in the model's memory, and the end of a part tells the model how to ask for the next one. You see the start position in the approval card.
- **It is told how much memory it has**, and its tool list is shorter, which leaves more room for your chat.
- **Calls:** the call screen no longer stays on "Saving" when the computer or the app never answers; an Answer that gets no reply gives up after 15 seconds and says so, so Decline is not left dead; a call that rang while the connection was down rings once it is back; and the call screen says when an agent's approval is waiting for the call to end.

## Fixes

- Calls: the call screen no longer stays on "Saving" when the computer or app never answers
- Calls: an Answer the computer never replies to no longer leaves Decline dead
- Calls: tapping Listen again while the app still listens no longer starts a second listen
- Calls: a new call that rang while the connection was down rings once it is back
- Calls: the call screen says when an agent's approval is waiting for the call to end
- Agents: a message that fails to send after you left and reopened the agent is put back
- Phone AI: Stop during a batch of tool calls runs none of the calls after it
- Calls: a recording that cannot be stopped is reported, and a lost answer says the call may still be open
- Phone app: an answered agent call keeps the microphone when you leave the app
- Phone app: a call rings as a full-screen notification and turns the screen on
- Phone AI trims a long chat to fit its memory before sending, instead of after an error
- Phone AI can read a long file in parts, and each part fills the room left in its memory
- Phone AI is told how much memory it has, and its tool list takes less of it
- Phone AI trims earlier questions' file texts before the one it is answering about

## Not done, and not checked

- Nothing was measured with the real model on a phone. The memory estimate is about 3 characters per token, not Qwen3's own tokenizer; whether the 1.7B model really asks for the next part of a file is untested. If the estimate is too low, the old retry after a "too long" error still applies; if too high, older turns are dropped a little early.
- The two Android app items above (the call service and the full-screen ring) are in the Android apps 1.0.472709, published on arcflare.net on 2026-11-25. Nothing ran on a phone.
- The phone page, including the phone AI changes above, is a copy bundled inside the Android app. The apps 1.0.472709 were built before these changes, so on a phone they arrive with the next app build; in a browser pointed at the hub's phone page they apply with this update.
- Calls still do not ring a frozen or killed app.

Update with `arcflare update`, or look first with `arcflare update --check`.
