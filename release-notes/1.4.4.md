ArcFlare 1.4.4: the AI on the phone can use your computer's MCP tools, and asks before every call.

## Changes you may notice

- **Arc Pocket Agent can use the tools of the MCP servers you have switched on.** This covers web search, the browser, desktop control, and any server you added from the store. It works in the app, signed in to your hub with an owner account.
- **It asks you before every single call.** The card shows the tool and exactly what will be sent, with two buttons: Allow and Do not allow. There is no "always allow". A question can make at most 3 calls.
- **What a tool returns is handed back as information, not instructions,** and is cut to fit the model's memory. The chat says when a tool call failed.
- **For ArcFlare's own phone tools** (`notify_phone`, `ask_phone`, `call_phone`), add `arcflare mcp` to `~/.arcflare/mcp.json` on the computer and switch it on in Tools. They are not built in.

## Fixes

- The approval card shows the whole input, and input too long to show is refused instead of cut off
- The approval card writes invisible and text-reversing characters out as \uXXXX, so what you read is what is sent
- The call that runs is the one you approved, even if the tool list reloads while the card is open
- A refused call (over 20 a minute) no longer starts the tool server first
- A tool server that fails to start is tried at most once a minute when the phone lists tools
- A tool call with parameters named `tool` and `args` no longer loses its other input
- Tool and parameter names are cleaned and capped before they reach the model's instructions

## Not done, and not checked

- Nothing ran on a phone. The figures come from our own runs of Qwen3-1.7B Q8_0 on a Linux computer, not published, 5 runs per task. With 10 tools it chose the right tool 5 of 5 times for the time in a city, a web search, a notification and "ring my phone". "Call me and say dinner is ready" made no call in all 5 runs: the model said it would call and did not. With 17 tools, "ring my phone" fell to 0 of 5. With many servers switched on the list the model sees gets shorter (descriptions first, then parameters), so switch on only what you need. The last wording changes to the instructions were not re-measured.
- Tool input over 1500 characters is refused.
- A server that keeps failing to start can still be started again on each call, up to 20 a minute.
- The 120 second limit on a call can be shorter than an `ask_phone` or `call_phone` wait.
- The phone page is a copy bundled inside the Android app: these changes reach a phone with a new app build.

Update with `arcflare update`, or look first with `arcflare update --check`.
