ArcFlare 1.4.0: crashes, hangs and unsafe paths fixed across the agent, the hub and the engine, after a code review of the whole CLI.

## Changes you may notice

- `arcflare rc relay` refuses a plain http address, except for localhost, so your session key is not sent in the clear. If you use a plain http relay, switch it to https before updating.
- Only an owner account can remove an agent and erase its saved conversation, and the phone's agent menu shows Delete only to owners.
- `arcflare mcp login` no longer signs in to a project's MCP server you have not trusted. Run `arcflare mcp trust` for the project first.
- One-time agents keep their undo snapshots in your ArcFlare folder (`~/.arcflare/onetime`), not the shared temp folder. The hub removes the old shared folder when it starts.
- A model or engine download that stalls fails after a minute without data. Run the same command again and it resumes.
- On Windows, a folder or argument with a % in it is refused, because cmd.exe expands it. Rename the folder.

## Fixes

- On Windows, a project folder with & or | in its name can no longer run a command
- mcp login no longer signs in to a project's MCP server you have not trusted
- A damaged session file can no longer make the agent delete folders outside its sessions
- Phone app chip says Relay, not Internet, when connected through the relay
- Phone app stops and reports it when the relay refuses it, instead of polling forever
- Hub no longer stops when it cannot save the agent list after a turn
- Hub no longer crashes when cloudflared's log file cannot be written
- Falling back from QUIC to HTTP/2 no longer leaves an extra cloudflared running
- A llama-server that cannot be run now gives an error instead of crashing ArcFlare
- Feeding input to a command that exits early no longer crashes the machine server
- Browser tools called at the same time no longer start a second, leaked browser
- Cancelling one generation job no longer cancels every job waiting behind it
- Model downloads refuse file names that would write outside the model cache
- Image and voice jobs keep their job file in ArcFlare's own folder, not shared tmp
- Desktop screenshots stay private to you and are deleted when the session ends
- arcflare rc relay refuses plain http, so your session key is not sent in the clear
- Machine server tools refuse arguments that are not an object instead of skipping checks
- The agent's bash tool no longer hangs when a command starts a background process
- An MCP server that stops reading or fails to start no longer crashes the agent
- MCP tools no longer get a server's own request back as the answer to a call
- Connecting to an MCP server that repeats its page cursor no longer hangs forever
- Team mode no longer cuts off a helper's answer by loading another model mid-request
- Team mode reports a helper llama-server that cannot start instead of crashing
- A pairing link with a broken %-escape is reported as a damaged link, not a crash
- Local AI shows why Delete or Stop sharing failed, and keeps the list current
- A chat opened twice in quick succession no longer shows each answer twice
- Turning YOLO or team mode on or off no longer changes the agent you switched to meanwhile
- Questions answered or closed while signed out no longer come back after signing in
- An approval waiting on screen comes back after a call that rang over it ends
- The fit check no longer claims 4K of context fits when the memory left holds less
- Switching llama.cpp builds no longer briefly shows the old build's GPU memory
- arcflare stop no longer kills an unrelated program left with the old server's PID
- smoke with an invalid ready_log pattern no longer leaves the app running
- Replacing a saved voice no longer deletes its clip before the new one is copied
- A model or engine download that stalls now fails after a minute instead of hanging
- arcflare fit can no longer be hung by the code a model writes for the add probe
- Only an owner account can remove an agent and erase its saved conversation
- The hub's relay connection no longer piles up listeners while it waits between polls
- Choosing an Arc on the phone no longer undoes a mute or hours set from the terminal
- run, use and the menu stop when the model fails to load instead of carrying on
- arcflare run shows the server's error instead of an empty reply, and no longer hangs
- The agent no longer waits forever when the model server dies mid-answer
- An agent edit no longer undoes a save you made while it waited for approval
- The mcp login callback page shows an error from the link as text, not as HTML
- A chat answer that cannot be saved now shows an error instead of answering forever
- arcflare phone relay prints a plain error for a bad address instead of a stack trace
- arcflare shop skips a catalogue entry with missing fields instead of crashing
- Tools switches on the phone refuse names like constructor instead of saving them
- Asking a call for a voice part it lacks now answers 400 or 404, not a server error
- Removing an account with a malformed name in the address answers 404, not a server error
- One-time agents keep undo snapshots in your ArcFlare folder, not the shared temp folder
- A removed agent no longer reappears in the event stream when its turn ends late
- On Windows, a folder or argument with % is refused, not expanded by cmd.exe
- A model download with one bad file name now writes nothing, not even the first file
- Hub start removes one-time agent files older versions left in shared temp
- The phone's agent menu shows Delete only to owner accounts

## Not done, and not checked

- The test suite passes on Linux, macOS and Windows (GitHub Actions). Nothing was tried by hand on Windows or macOS, so the Windows quoting, the % refusal, the screenshot folder and the check that `arcflare stop` signals the right process have not been run on a real machine.
- Two changes were held back for a decision: checking llama.cpp downloads against the checksum GitHub publishes, and keeping the paired-phones list for a few seconds when its file cannot be read. Until then, llama.cpp downloads are not checked against a published checksum.
- Known and not fixed: the web tool can be pointed at a private address by DNS rebinding, the browser tools start Chrome with its sandbox off when run as root, and code a model writes for `arcflare fit` runs in Node's vm module, which is not a sandbox.
